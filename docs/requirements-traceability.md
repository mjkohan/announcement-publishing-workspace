# Requirements traceability

This document maps every requirement in [ASSIGNMENT.md](ASSIGNMENT.md) to the code that implements
it and the tests that verify it. Requirements are taken sentence by sentence from the brief
(statements with "must", "let users", "show", "keep", "do not" and equivalent wording).

Line references point to the state of the repository when this file was written. Paths are
relative to the repository root.

Status values:

- **Met**: implemented and covered by at least one automated test.
- **Met (no test)**: implemented by design; an automated test does not apply (for example, a
  feature that must not exist).
- **Weak**: implemented, but the test coverage or the user-facing behavior is incomplete.
- **Gap**: missing.
- **N/A**: out of scope or not a product requirement.

## Gaps and weak points

1. **Blocked publish has no UI (3.3).** When the journal write fails, the store refuses the publish
   and sets `publishBlocked` (`src/store/publicationStore.ts:491`), but no component renders it.
   The user clicks Publish and nothing visible happens. `dismissPublishBlocked` is exported from
   `src/app/hooks.ts:41` but unused.
2. **No guard for unchanged mocks (3.2, 4.2).** Nothing in `npm run check` or CI verifies that
   `src/mocks` still matches the supplied files.
3. **Cross-announcement error isolation is not tested (2.14).** No test leaves one announcement in
   "Outcome unknown" or stale "Processing" and then publishes another one.
